## Section 1: Unit Test สำหรับ `isValid`

### Prompt

> [!NOTE]
> **Prompt**
>
> เอ้ยทำ test ให้ข้อ 1 ด้วยนะ

### Answer

> [!TIP]
> **Answer**
>
> #### 1. การเปลี่ยนแปลงใน `validString.ts`
>
> เพิ่ม `export` ให้ `isValid` เพื่อให้ไฟล์ test import ได้ ไม่ได้แก้ logic และ `console.log` ตัวอย่างเดิมยังอยู่
>
> #### 2. Unit Test (`question1/validString.test.ts`)
>
> ใช้ `node:test` + `node:assert/strict` เหมือนข้ออื่น มี 23 tests ใน 4 suites:
>
> 1. **ตัวอย่างเดิมใน `validString.ts`:** 8 ตัว (`()`, `([]]`, `([{}])`, `([[{}]]]`, `)`, `(]}])`, `([)]`, `{`)
> 2. **Input ที่ถูกต้อง:**
>    - วงเล็บแต่ละแบบ (`()`, `[]`, `{}`)
>    - วางต่อกัน (`()[]{}`)
>    - ซ้อนกัน (`{[()]}`, `((()))`)
>    - ซ้อนกันและวางต่อกัน (`{[]}([{}])[]`)
>    - string ว่าง
>    - input ยาว 10,000 ตัว
> 3. **Input ที่ไม่ถูกต้อง:**
>    - มีแต่วงเล็บเปิด หรือมีแต่วงเล็บปิด
>    - ปิดก่อนเปิด (`)(`)
>    - ชนิดวงเล็บไม่ตรงกัน (`(]`)
>    - ปิดผิดลำดับ (`([)]`)
>    - มีวงเล็บเปิดหรือปิดเกินท้าย (`()(`, `())`)
>    - input ยาวที่ขาดวงเล็บปิด 1 ตัว
> 4. **ตัวอักษรอื่นที่ไม่ใช่วงเล็บ (lock พฤติกรรมปัจจุบันไว้):** `a`, `(a)`, `( )`, `<>` คืน `false`
>
> #### 3. พฤติกรรมที่ test ยืนยันไว้
>
> - **string ว่าง** คืน `true` เพราะไม่มีวงเล็บที่ต้องปิด
> - **ตัวอักษรที่ไม่ใช่ `( ) [ ] { }`** ทำให้คืน `false` ทันที รวมถึงช่องว่าง ถ้าต้องการให้ข้ามตัวอักษรอื่น ต้องแก้ `isValid` และแก้ test ชุดที่ 4
>
> #### 4. วิธีรันและผลการรัน
>
> ```bash
> cd question1
> node validString.ts               # demo
> node --test validString.test.ts   # unit test
> ```
>
> ```
> ℹ tests 23
> ℹ suites 4
> ℹ pass 23
> ℹ fail 0
> ```
>
> ตรวจ type ของ `validString.ts` ด้วย `tsc --strict` แล้ว ไม่มี error
